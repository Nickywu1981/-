# ADR-023: 可视化画布拼装落地策略

**日期**: 2026-05-14
**状态**: 已定版
**决策者**: G1 架构规划组

---

## 背景

项目需要实现可视化画布拼装功能，支持"拖拽→生成页面→绑定事件→调用接口→保存并渲染"核心链路。
经过三轮深度评估（组件架构/API 契约/权限体系/SDK 方案），现有结论如下。

---

## 评估结论

### 组件封装度：3.75/10

| 标准 | 评分 | 现状 |
|------|:---:|------|
| 可注册 | 5/10 | `useDiyComponents.ts` 静态注册 12 个组件 |
| 可配置 | 7/10 | `ComponentProp` 8 种类型，条件显隐 |
| 可拖拽 | 3/10 | 原生 HTML5 DnD，vuedraggable 已安装未启用 |
| 可绑定 | 0/10 | 零实现 — 无事件/数据源/插槽元数据 |

### 架构支撑度

| 层次 | 评分 | 关键缺口 |
|------|:---:|---------|
| 后端 6 层架构 | 7.5/10 | Controller/Service/DAO 三件套完整 |
| 权限体系 | 3/10 | 无资源实例级 ACL，`owner_id` 不生效 |
| 多租户 | 8/10 | TenantPool 自动注入，租户内无再细分 |
| API 契约 | 6/10 | 统一格式 100%，但 Section 用 `z.unknown()` 透传 |

### 工作台 55 页硬编码：不需要改造

画布产出 **营销落地页**，工作台是 **AI 工具界面**，两者正交。画布不替代工作台，工作台不转换为画布。

### SDK 方案：现阶段不引入

现有 DIY Schema 已提供 85% 能力，SDK 预留以下触发条件：
- C1: 第三方开发者注册自定义组件
- C2: 画布嵌入外部应用
- C3: 组件市场（社区贡献）
- C4: B 端白标自定义组件
- C5: 组件数 > 50 个，源码注册无法维护

---

## 决策

**选择方案 A：最小改动路线**

1. 基于现有 DIY 系统升级，不推倒重来
2. 工作台 55 页保持不动
3. SDK 暂不引入，根据触发条件决定启动时机
4. 画布目标：电商营销落地页拼装

---

## S1-S7 落地路径

| 步骤 | 内容 | 改什么 | 周期 |
|------|------|--------|:---:|
| **S1** | `shared/types/diy.ts` 统一前后端类型 | 新增 1 文件 | 2d |
| **S2** | `DiyComponent` 扩展 `events/slots/constraints` 字段 | 改 1 类型文件 | 2d |
| **S3** | `DiySectionPreview.vue` v-if 链 → 动态 `:is` 渲染 | 重构 1 文件 | 4d |
| **S4** | `diyRoutes.js` Zod 从 `z.unknown()` 升级强类型 | 改 1 路由文件 | 2d |
| **S5** | 新增 `ownershipGuard` 中间件，补位页面级权限 | 新增 1 + 改 1 | 2d |
| **S6** | `editor.vue` 引入 vuedraggable 替代原生 HTML5 DnD | 改 1 页面文件 | 3d |
| **S7** | Section 扩展 `position` 字段 (x,y,w,h,z) | 纯数据层扩展 | 2d |

**总周期**: 4-5 周
**破坏性**: 零。仅改 `diy` 模块，不影响 204 个业务页面
**向后兼容**: `mobile`/`pc` 页面类型不变，新增 `canvas` 类型

### 就绪门槛: S1-S5（2 周）

完成 S1-S5 后即可进入 Phase 2 事件绑定和画布体验开发。

### 不改的部分

- 不重构 12 个 DIY 组件（仅加 metadata 导出）
- 不修改 6 层后端架构
- 不修改权限中间件链（仅新增 ownershipGuard）
- 不影响 55 个 work 页面
- 不修改数据库表结构（仅扩展 JSON 字段）
