# Decision 026: v1/v2 对标评估 — Movio AI 现状成熟度审计

**日期**: 2026-05-15 | **状态**: 纯评估，不排期 | **关联**: Decision 025 (三端架构), Decision 024 (全链路分阶段)

---

## 零、参考基线定义

### v1（简陋版）
- 后端：裸 Express 端点，直接调 AI 模型 API，无中间件管线
- 代码执行：`child_process.exec()` 本地执行，无沙箱
- AI 编程：无 Agent，无自我迭代
- 文件存储：本地 `uploads/` 目录，无隔离
- 输出面板：单一 `<img>` 或 `<pre>` 标签展示结果
- 基础设施：从零自研，无复用基础
- 安全：仅 JWT 登录，无执行隔离

### v2（成熟版，OpenClaw + E2B）
- 后端：标准化分组 API（`/v2/images`, `/v2/agents`），SDK 层
- 代码执行：E2B 云端沙箱，多语言，网络隔离，配额管控
- AI 编程：Agent 自主迭代、流式代码修改、自我修复
- 文件存储：多租户隔离（S3/COS/OSS），CDN 分发
- 输出面板：终端 + 预览 + 对话三面板并排
- 基础设施：OpenClaw Agent 框架 + E2B 沙箱 + 素材管线
- 安全：执行隔离 + 并发限制 + 文件大小限制 + 细粒度权限

## 三、v2 成熟方案相对我们的核心优势/风险/成本

### 3.1 核心优势

| v2 能力 | 对 Movio AI 的价值 | 紧迫度 |
|------|------|:--:|
| **OpenClaw Agent 生态** | 可复用社区 Agent，不需要每个 Agent 从零写 | 低 (Agent 非当前重点) |
| **自主迭代 Agent** | Agent 写代码→执行→看结果→自我修复 | 低 (同上) |
| **云存储 (S3/COS/OSS)** | 用户素材持久化、CDN 加速、多租户隔离 | **高** |
| **多面板输出** | 终端日志 + 预览 + AI 对话并排 | **中** |
| **素材处理管线** | 自动裁剪/压缩/水印/转码 | **高** |
| **SDK 层** | 第三方开发者可集成 Movio AI API | 低 (无第三方开发者) |
| **消息队列 (BullMQ)** | 异步任务可靠执行，替代 MySQL 轮询 | **中** |

### 3.2 风险

| 风险 | 说明 |
|------|------|
| **OpenClaw 耦合** | 引入外部 Agent 框架后，ADK 自研 2100 行代码面临废弃或适配 |
| **Agent 自主迭代** | 让 Agent 写代码并执行 = 新的攻击面（已通过 E2B 沙箱缓解，但代码生成质量不可控） |
| **云存储迁移** | 从本地磁盘迁到 COS/OSS 涉及全部上传逻辑重写 + 历史数据迁移 |
| **多面板 UI 改造** | WorkPipeline 的 6 种 resultMode 需要重构为多面板架构，改动量大 |
| **过度建设** | 当前无第三方开发者、无 Agent 自主迭代需求，v2 多项能力是"未来可能需要" |

### 3.3 成本估算

| v2 模块 | 开发量 | 说明 |
|------|:--:|------|
| 云存储迁移 | 8d | COS/OSS SDK 集成 + 多租户分桶 + 迁移脚本 |
| 素材管线 | 5d | 裁剪/压缩/水印/转码 service |
| 多面板 UI | 8d | WorkPipeline 重构为 PanelLayout |
| BullMQ 替换 | 3d | 从 MySQL 轮询 → Redis 队列 |
| Agent 自主迭代 | 15d+ | 代码生成→沙箱执行→结果分析→自我修复 |
| SDK 层 | 5d | OpenAPI 文档生成 + 多语言 SDK |
| OpenClaw 适配 | 10d+ | ADK → OpenClaw 迁移 |
| **合计** | **54d+** | 不含测试/文档/迁移验证 |

## 四、三端架构适配性

结合 Decision 025 选定的 3 端改良架构，评估 v2 各模块的适配性:

| v2 模块 | 端1 (总后台) | 端2 (运营后台) | 端3 (用户工作台) | 适配性 |
|------|:--:|:--:|:--:|:--:|
| **云存储** | COS/OSS 配置 | 存储用量监控 | 用户素材上传/管理 | ✅ 三端都涉及 |
| **素材管线** | 管线配置 | 审核/统计 | 用户触发处理 | ✅ 三端都涉及 |
| **多面板 UI** | — | — | 工作台核心体验 | ✅ 仅端3 |
| **BullMQ** | 队列监控 | 任务监控 | 异步任务提交 | ✅ 三端都涉及 |
| **Agent 自主迭代** | — | — | Agent 交互界面 | ⚠️ 仅端3, 且非当前重点 |
| **SDK** | — | — | 第三方开发者门户 | ❌ 当前无场景 |
| **OpenClaw** | — | — | — | ❌ ADK 自研够用 |

**适配结论**: v2 的前 4 项（云存储/素材管线/多面板/BullMQ）与三端架构高度适配，且分散在三个端。后 3 项（Agent 自主迭代/SDK/OpenClaw）当前无业务场景。

## 五、定性结论: 哪些 v2 模块价值最大、哪些暂时无用

### ✅ 高价值 (应尽快做)

| 模块 | 理由 | 挡了什么 |
|------|------|------|
| **云存储 (COS/OSS)** | 用户素材越来越多，本地磁盘不可扩展，无 CDN 导致加载慢，无租户隔离是安全隐患 | 素材库功能、多租户安全、大文件上传 |
| **素材管线 (裁剪/压缩/水印)** | 用户上传的图片/视频需要自动处理为平台标准格式 | 图片扩图/视频合成的输入标准化 |
| **BullMQ 消息队列** | MySQL 轮询队列性能差、不可靠、不支持优先级/延迟 | 异步任务可靠性、批量任务 |

### ⚠️ 中价值 (图片/视频稳定后做)

| 模块 | 理由 |
|------|------|
| **多面板 UI** | 终端+预览+对话并排体验更好，但当前单面板够用。等 WorkPipeline 稳定后再改 |
| **Agent 自主迭代** | 技术上最亮眼，但当前图片/视频创作不需要 Agent 写代码。Python 数据挖掘阶段再启动 |

### ❌ 暂无用 (当前阶段不做)

| 模块 | 理由 |
|------|------|
| **OpenClaw 框架** | ADK 自研 2100 行满足当前编排需求，换框架成本 > 收益 |
| **SDK 层** | 无第三方开发者，无 API 商业化计划 |
| **Agent 市场** | 无 Agent 生态，无社区 |
