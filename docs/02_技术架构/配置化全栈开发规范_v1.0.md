# Movio AI 配置化全栈开发规范 v1.0

> G1 架构规划 | 2026-05-08 | 唯一开发标准
> 
> 核心铁律：**所有文案、选项、分类、参数、模板不写死，统一走配置中心**

---

## 一、配置化设计总则

### 1.1 核心原则

| 原则 | 说明 |
|:--|:--|
| **零硬编码** | 前端文案、后端字段名、下拉选项、模板内容一律不可出现在代码中 |
| **配置即数据** | 所有可变内容存储在 MySQL，Redis 做缓存，前端通过 API 动态获取 |
| **后台可视编辑** | 管理后台提供表单式编辑，支持新增/修改/删除/排序/启用停用 |
| **热更新** | 修改配置后实时生效，无需重启服务或重新部署 |
| **命名空间隔离** | 按模块/页面/组件三级命名空间组织，避免冲突 |

### 1.2 配置分类体系

| 配置类型 | 命名空间前缀 | 说明 | 示例 |
|:--|:--|:--|:--|
| **页面文案** | `page.` | 页面标题、副标题、引导文案、空状态 | `page.home.hero.title` |
| **组件文案** | `comp.` | 按钮、表单标签、占位符、提示 | `comp.upload.btn_text` |
| **菜单导航** | `nav.` | 导航名称、面包屑、tab标签 | `nav.sidebar.video_label` |
| **业务字典** | `dict.` | 下拉选项、分类、类型枚举 | `dict.video_duration_options` |
| **模板内容** | `tpl.` | 提示词模板、回复模板、消息模板 | `tpl.prompt.image_optimize` |
| **系统参数** | `sys.` | 限制值、开关、阈值、URL | `sys.upload.max_size_mb` |
| **会员/分销** | `biz.` | 套餐名、价格、返利比例、等级名 | `biz.member.plans` |

## 四、前端架构设计 — G4 执行

### 4.1 Composable: `useAppConfig`

```typescript
// client/composables/useAppConfig.ts

/**
 * 获取页面/组件配置文案
 * 用法: const { config, loading } = useAppConfig('page.home')
 * 模板: <h1>{{ config.title }}</h1>
 */
export function useAppConfig(groupKey: string) {
  const config = ref<Record<string, any>>({})
  const loading = ref(false)
  
  const fetch = async () => {
    loading.value = true
    const { data } = await useFetch(`/api/config/${groupKey}`)
    config.value = data.value ?? {}
    loading.value = false
  }
  
  // SSR 首屏用 useAsyncData，客户端用缓存
  if (import.meta.server) {
    const { data } = await useAsyncData(`config:${groupKey}`, 
      () => $fetch(`/api/config/${groupKey}`))
    config.value = data.value ?? {}
  } else {
    await fetch()
  }
  
  return { config: readonly(config), loading, refresh: fetch }
}
```

### 4.2 Composable: `useAppDict`

```typescript
// client/composables/useAppDict.ts

/**
 * 获取业务字典（下拉选项）
 * 用法: const { options } = useAppDict('video_duration')
 */
export function useAppDict(dictKey: string) {
  const options = ref<DictItem[]>([])
  const loading = ref(false)
  
  const fetch = async () => {
    loading.value = true
    const { data } = await useFetch(`/api/dict/${dictKey}`)
    options.value = data.value ?? []
    loading.value = false
  }
  
  // 同上 SSR/客户端分叉
  await fetch()
  
  return { options: readonly(options), loading, refresh: fetch }
}
```

### 4.3 Composable: `useAppPage`

```typescript
// client/composables/useAppPage.ts

/**
 * 页面级配置入口，一次性加载页面所需的全部分组配置和字典
 * 用法: const { texts, dicts, loading } = useAppPage({
 *   configs: ['page.video', 'comp.upload', 'comp.video_card'],
 *   dicts: ['video_duration', 'video_ratio', 'video_style']
 * })
 */
export function useAppPage(def: PageConfigDef) {
  const texts = ref<Record<string, Record<string, any>>>({})
  const dicts = ref<Record<string, DictItem[]>>({})
  const loading = ref(false)
  
  const fetch = async () => {
    loading.value = true
    // 一次请求拿全部
    const { data } = await useFetch('/api/config/batch', {
      method: 'POST',
      body: {
        groups: def.configs,
        dicts: def.dicts
      }
    })
    texts.value = data.value?.configs ?? {}
    dicts.value = data.value?.dicts ?? {}
    loading.value = false
  }
  
  await fetch()
  return { texts, dicts, loading, refresh: fetch }
}
```

| 模板管理 | `/admin/config/templates` | 模板列表，按分类筛选 |
| 模板编辑 | `/admin/config/templates/:key` | 模板内容编辑 + 变量预览 |
| 套餐配置 | `/admin/config/membership` | 会员套餐名/价格/权益编辑 |

### 6.2 后续新增功能的配置化流程

当需要新增功能 `X` 时，无需改核心代码，标准流程：

| 步骤 | 操作 | 负责人 |
|:--|:--|:--:|
| 1 | 在管理后台新建配置分组 `page.x` | 运营 |
| 2 | 在分组下新增配置项（标题/按钮/提示等） | 运营 |
| 3 | 如需要新下拉选项，新建字典组 `dict.x_options` | 运营 |
| 4 | 前端页面用 `useAppPage({ configs: ['page.x'], dicts: ['dict.x_options'] })` | G4 |
| 5 | 组件中用 `texts['page.x'].xxx` 读取文案 | G4 |

**核心代码只需新增页面/组件本身，所有文案和选项通过后台配置录入，不需要动配置系统。**
